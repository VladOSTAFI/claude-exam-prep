## Why naive RAG fails

When you chunk a document and embed each chunk in isolation, **chunks lose surrounding context**. A chunk that says:

> "Q3 revenue rose 5%."

…is ambiguous. Whose Q3? Which company? Which year? The embedding for this chunk is also ambiguous, so retrieval misses it on a query like "What was Acme's 2025 third-quarter revenue growth?"

## The three layers

### Layer 1 — Contextual Embeddings

Before embedding, prepend each chunk with a 50–100 token contextualizing summary generated by Claude. The summary explains **what document this chunk is from and what came before**.

```
[CONTEXT]
This chunk is from Acme Corp's Q3 2025 earnings report, in the
"Financial Performance" section. It follows discussion of full-year
guidance and precedes the regional breakdown.
[/CONTEXT]

[ORIGINAL CHUNK]
Q3 revenue rose 5%.
[/ORIGINAL CHUNK]
```

The combined text is what gets embedded. The chunk now carries its context in the vector.

### Layer 2 — Contextual BM25

Apply the same context-prepending to **BM25 (keyword)** search. Then fuse vector + BM25 results using **Reciprocal Rank Fusion (RRF)**.

**Why both?** Vector catches semantic similarity. BM25 catches **exact terms** — IDs, error codes, acronyms, rare names. They cover different failure modes.

### Layer 3 — Reranking

Run a cross-encoder reranker (e.g., **Cohere Rerank**, **Voyage Rerank**) over the top-N (say top-20) before final pick. The reranker is more expensive per pair but more accurate; you only pay for it on a small candidate set.

## Why prompt caching is what makes this affordable

Without caching, contextualizing 1,000 chunks of a 100k-token document means **paying for the document 1,000 times**. With caching:

- **Cache the full document** at the start.
- **Vary only the chunk** in the contextualization call.
- Cache reads cost **~10% of input price**. Cache writes cost **1.25×** (5-min TTL) or **2×** (1-hr TTL).

Net effect: per-chunk contextualization becomes economically viable. Without caching, the cost would be ~10× higher.

### Prompt caching mechanics

| Item | Value |
|---|---|
| Cache hierarchy | **Tools → System → Messages** (cached top-down) |
| Max breakpoints | 4 |
| Default TTL | 5 minutes |
| Extended TTL | 1 hour (available) |
| Cache write cost | 1.25× input (5m) / 2× input (1h) |
| Cache read cost | ~10% of input price |
| Invalidation | Changing tool definitions invalidates downstream cache |

## Hybrid search — RRF in practice

```ts
// Reciprocal Rank Fusion — combine vector and BM25 rankings
function rrf(rankings: number[][], k = 60): number[] {
  const scores = new Map<number, number>();
  for (const ranking of rankings) {
    ranking.forEach((docId, rank) => {
      scores.set(docId, (scores.get(docId) ?? 0) + 1 / (k + rank + 1));
    });
  }
  return [...scores.entries()]
    .sort(([, a], [, b]) => b - a)
    .map(([docId]) => docId);
}
```

## Citations — grounding answers in sources

Anthropic's [citations API](https://platform.claude.com/docs/en/build-with-claude/citations) lets Claude cite the exact passages it used. This:

- Reduces hallucination.
- Lets users verify answers.
- Provides audit trails for compliance.

```ts
const response = await claude.messages.create({
  model: "claude-sonnet-4-6",
  messages: [{
    role: "user",
    content: [
      {
        type: "document",
        source: { type: "text", media_type: "text/plain", data: chunk1 },
        citations: { enabled: true },
      },
      { type: "text", text: "What was Q3 revenue growth?" },
    ],
  }],
});
```

## Chunking guidelines

| Property | Recommendation |
|---|---|
| Size | ~200–500 tokens (sweet spot) |
| Method | Token-based (use a tokenizer, not character count) |
| Overlap | 10–20% to preserve cross-chunk context |
| Boundary | Don't split mid-sentence; prefer paragraph or section breaks |

## Hands-on exercise — three steps

### Step 1 — Baseline RAG (45 min)

```ts
// Pseudocode flow
const chunks = chunkDocument(doc, { size: 300, overlap: 50 });
const embeddings = await embedAll(chunks); // Voyage or OpenAI
await pgvector.insert(chunks, embeddings);

// Query
const queryEmbedding = await embed(query);
const top10 = await pgvector.cosineSearch(queryEmbedding, 10);
const answer = await claude.messages.create({
  model: "claude-sonnet-4-6",
  messages: [{
    role: "user",
    content: [
      ...top10.map(chunk => ({
        type: "document",
        source: { type: "text", data: chunk.text },
        citations: { enabled: true },
      })),
      { type: "text", text: query },
    ],
  }],
});
```

### Step 2 — Add contextualization (30 min)

For each chunk, call Claude (with the **whole document cached**) to generate a 1–2 sentence context. Prepend, then re-embed.

```ts
async function contextualize(doc: string, chunk: string) {
  const res = await claude.messages.create({
    model: "claude-haiku-4-5-20251001",
    system: [
      { type: "text", text: doc, cache_control: { type: "ephemeral" } },
    ],
    messages: [{
      role: "user",
      content: `Provide a 1-2 sentence context for the following chunk, situating it in the document. Output ONLY the context.\n\nChunk:\n${chunk}`,
    }],
  });
  return res.content[0].text;
}
```

Re-run queries on the same 10 hand-picked test questions. Compare retrieval quality.

### Step 3 — Add hybrid + (optional) rerank (45 min)

- Add BM25 over the same contextualized chunks (`pg_search` or in-memory).
- Fuse vector + BM25 with RRF.
- Optionally call Cohere Rerank or Voyage Rerank on top-20 → top-5.

## Exam traps to reject

| Tempting wrong answer | Why it's wrong |
|---|---|
| "Just use a bigger context window — RAG is obsolete" | Cost, latency, attention all suffer |
| "Vector search alone is enough" | Misses exact-match queries (IDs, error codes) |
| "Re-embed without contextualization to save cost" | The contextualization step IS the win |
| "Skip prompt caching for the contextualization pass" | Cost explodes ~10× |
| "Pick the vector DB with the highest benchmark score" | Pick the one that fits your ops stack |
| "Skip citations — Claude is reliable enough" | Citations reduce hallucination and provide audit trails |

## Production-grade RAG architecture

```
                ┌─ Vector Index (contextualized chunks) ──┐
                │                                         │
[Query] ─→ Embed ┤                                         ├─→ RRF Fusion ─→ Rerank ─→ Top-K ─→ Claude (with citations) ─→ [Answer]
                │                                         │
                └─ BM25 Index (contextualized chunks) ────┘
```

## Quick reference

| Layer | Tool | Why |
|---|---|---|
| Chunking | Tokenizer-aware splitter | Don't split mid-sentence |
| Contextualization | Claude Haiku + prompt caching | Cheap with caching, expensive without |
| Vector search | pgvector / Pinecone / Qdrant | Semantic similarity |
| Keyword search | BM25 | Exact terms, IDs, rare words |
| Fusion | RRF | Combine the two rankings |
| Reranking | Cohere / Voyage | Precision boost on top-N |
| Generation | Claude w/ citations | Grounded answers, reduced hallucination |
